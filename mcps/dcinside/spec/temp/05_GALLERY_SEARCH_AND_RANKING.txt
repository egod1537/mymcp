# 05 / 특정 갤러리 검색 품질 향상

[문제점 - 현재 코드]
Brave 검색 요청은 기본적으로 `site:gall.dcinside.com <query>`만 보내고, galleryId/galleryType은 Brave 결과를 받아온 뒤 필터링한다.
따라서 관련 갤러리 결과가 처음 N개에 포함되지 않으면 결과가 0개로 보이기 쉽다.
또한 Brave가 보여주는 dateLabel은 검색 인덱스 age이며 게시글 게시 시각이 아니다.

[개선 목표]
- galleryId 지정 시 관련 URL을 검색 단계부터 우선하도록 query builder 추가.
- 최소 데이터 비용으로 충분한 후보 결과를 수집하고 canonical URL로 dedupe.
- local imported search results를 검색 가능하게 하고 Brave와 명시적으로 선택 가능.
- 검색 결과 출처/정확도/날짜 근거를 사용자에게 투명하게 표시.

[Brave Query Builder]
1. galleryId/galleryType 없이: 기존 `site:gall.dcinside.com <keyword>` 유지.
2. 갤러리 지정 시: 적합한 갤러리 URL 패턴 및 id query를 키워드 후보로 사용하되 Brave 지원 연산자를 확인해 테스트로 입증. 예) `site:gall.dcinside.com "id=japan" <keyword>`는 시험용 후보이며 동작을 단정하지 말 것.
3. 1차 검색으로 exact filter 통과가 적을 때 controlled fallback query를 1회 실행. source-of-truth는 parseDcPostUrl 후 galleryId == requested ID.
4. 편향/조회비용을 측정하고 실효성이 없는 query 변형은 제거. 과도한 반복 쿼리 X.
5. galleryType는 major/minor/mini URL 경로 매핑으로 필터; URL type은 parseDcPostUrl 반환값 우선.
6. Brave API `offset`/`count`가 허용되는 범위만 사용. 이전에 지원되지 않는 offset을 하드코딩하지 말 것.

[검색 스코어]
- 입력 후보: {query, matchedKeywords, title, snippet, canonicalUrl, galleryId, galleryType, postNo, indexedAge?,source}
- 정확한 갤러리 일치가 최우선, 다음으로 제목 exact phrase, 토큰 포함, snippet 일치, 검색 provider rank.
- 사용자 지정 sort='relevance' -> 안정적인 점수 정렬; sort='latest' -> 명시적 게시 날짜가 있을 때 그 날짜, 없을 경우 동일 갤러리 내 postNo DESC를 근사치로 사용. 타 갤러리 간 postNo 비교 금지.
- 'latest'를 실제 사이트의 최신 게시물과 동일하다고 주장하지 말고 estimatedSort:true 제공.
- duplicate key: canonicalUrl; 같은 ID의 URL은 query parameter 제거 canonicalizer 사용.
- matchedKeywords: 여러 검색어에서 찾은 키워드 집합(입력 순서 유지); 합산 시 결과 순서 분리하지 않음.
- fetch 결과 수와 filter 후 수, provider quota, dedupe 후 수 집계.
- 결과가 없어도 `reason`을 명확하게: no-index-match / gallery-filtered-out / provider-failed / local-index-empty.

[Deep-search로부터 참고하는 독립 로직]
- 수동 export에 포함된 keyword, searchType, searchStep을 보존.
- 하나의 게시글이 여러 검색어와 매칭되면 metadata 병합.
- 검색 pagination은 해당 export의 provenance 정보만 유지, mymcp 서버는 자동 페이지 순회하지 않음.
- CSV import 후에는 galleryId, keyword, title, body preview(있는 경우)를 로컬 검색할 수 있게 함.

[성능 상한]
- API 호출수 최대 1..3 요청/사용자 실행, 애매한 결과 재시도는 budget 공유.
- 동시 검색 수 제한, 타임아웃, 비정상 API 응답 명확히 구분.
- 짧은 TTL cache 선택: key=(provider,galleryId,type,query,sort,offset), 금액/쿼터 정보 로그에는 비밀 제외.
- 검색 결과는 상한 20 items/default, source별 count 보고.

[테스트 사례]
A. 같은 query, galleryId 없음 -> 기존 테스트 결과 유지.
B. galleryId 지정, provider 첫 결과 20개 모두 타갤러리 -> 결과에 섞이지 않음, fallback budget/빈 사유 확인.
C. 동일 글 URL에 page, ref parameter 달라도 한 건.
D. 최신/관련도 정렬, 게시일 없는 레코드, 여러 갤러리 혼합, 동점 순서 검증.
E. keywords ["항공", "취업"]일 때 중복 1건 + matchedKeywords 두 개.
F. 키 없는 Brave 검색 -> CONFIGURATION_REQUIRED, 로컬 검색은 계속 사용 가능.
