# 02 / 외부 프로젝트 활용 전략 및 소스 검증

[A] @gurumnyang/dcinside.js
GitHub: https://github.com/GurumNyang/dcinside.js
NPM: https://www.npmjs.com/package/@gurumnyang/dcinside.js
확인된 repo package.json: version 1.15.2, main=dist/index.js, types=dist/index.d.ts, MIT LICENSE.
확인된 공개 함수: getPostList, getPost, getPostListLegacy, getPostLegacy, getPosts, search.
index.ts는 export = { ... } 형태의 CommonJS API.
getPostList({page,galleryId,boardType}) -> PostInfo[]
getPost({galleryId,postNo,...}) -> Post | null; Post.comments에 댓글이 포함될 수 있음.
search(query, {sort:'latest'|'accuracy'}) -> SearchResult.

실행 계획:
1. 실제 레포/배포 버전을 확인하고 호환되는 정확한 버전 고정. 'latest' 무작정 사용하지 말고 Node22/TS6/ESM interop 검증.
2. 라이브러리를 dcinside adapter 단일 경로에서만 require. 예: Node ESM의 createRequire(import.meta.url) (코드 스타일은 실제 컴파일 기준).
3. 원본 함수 결과를 도메인 normalized schema로 매핑. 외부 타입을 MCP tool signature에 노출하지 않음.
4. 직접 호출을 위한 권한/범위 검증 이전에는 mock 객체를 주입한 adapter 테스트만 수행. 프로세스 실행 시 무조건 fetch하지 않음.
5. 허가된 환경에서만 허용되는 wrapper 메서드 (listPosts, getPost, search). 다른 외부 라이브러리 함수는 require하더라도 노출하거나 호출하지 않음.
6. 라이브러리 로그(stdout) 또는 라이브러리 내부 재시도/요청량도 조사. stdio 오염 발견 시 별도 child process/worker 분리 등 안전한 경로 선택.
7. 재배포 시 MIT 원문 저작권/라이선스 고지 보존. dependency 추가만으로 MIT가 데이터 수집 권한을 주는 것은 아님.

[B] sendhyun/dcinside-deep-search
GitHub: https://github.com/sendhyun/dcinside-deep-search
확인된 파일: manifest.json, src/parser.js, src/csv.js, src/crawler.js.
확인된 설계: Chrome MV3 side panel, 다중 키워드 순차 검색, matchedKeywords 축적, 중복 제거, 최신순 정렬, CSV export.
CSV 열 예: index,galleryId,keyword,searchType,title,author,date,views,recommends,commentCount,postId,url,searchStep,sourceUrl.
README: search_pos는 실제 HTML의 '다음 검색' link 후보를 검증할 때만 사용, 임의 page 생성 X.
라이선스: 현재 GitHub repo metadata에 license=null, LICENSE 파일 미확인. 무단으로 내부 소스/셀렉터 테이블을 복사하지 말 것.

실행 계획:
1. '기존 확장 프로그램을 이용해 사용자가 직접 CSV 내보내기' -> mymcp가 파일 import하는 인터페이스를 제공.
2. CSV 포맷을 근거로 새로운 import parser와 병합/정렬 구현. 출처 reference 문서화.
3. 사용자 제공 JSON export도 지원하되, 원본 확장 프로그램에 JSON export 기능이 있다고 가정하지 말 것. JSON은 mymcp가 정의한 데이터 입력용.
4. 브라우저 확장 프로그램 자체를 복제하거나 내부 자동 탐색 코드(search_pos traversal 등)를 포팅하지 않음.
5. 원본 코드 재사용 또는 원본 수정본 배포가 필요하면 먼저 저작권자로부터 허락/라이선스를 확인하고 별도 PR로 관리.

[공통 품질 요건]
- 출처, API 버전, 접근권한, 라이선스, 데이터 출처/시각을 문서화.
- 결과의 source는 brave_index, user_import, deep_search_export, authorized_direct 등으로 명확히 나눔.
- 자동 요청 제한을 내부 라이브러리 retry와 별도로 정의. 실패 시 '없음'으로 위장하지 않음.
- 원문 저장은 보관 권한이 있는 데이터에 한정, 최소한의 텍스트 필드만 기본 저장.
