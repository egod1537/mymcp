[목적]
현재 DCInside MCP는 Brave 제3자 인덱스에 기반하여 결과가 빈약하며, 게시글 본문/댓글은 수동으로 import한 뒤에만 조회할 수 있다. 기존 코드와 Tool 이름을 최대한 유지하면서 다음을 추가한다.
- 갤러리 ID로 한정한 검색과 검색 품질 측정/개선
- 게시글 목록, 본문, 댓글, 본문+댓글 통합 조회의 일관된 MCP 인터페이스
- @gurumnyang/dcinside.js의 공개 타입/코드를 직접 활용한 독립 adapter
- dcinside-deep-search의 검색 결과 CSV를 명시적으로 가져오는 importer + 병합/정렬 알고리즘 자체 구현
- 단일 게시글에 대한 사용자 제공 HTML/JSON import, Provenance/업데이트 시각 표기
- 기존 Blueprint Console이 있다면 동일한 디자인으로 검색·읽기·오류·소스 표시
- 오프라인 자동 테스트, 보안, 실행 제한, 실행 안내, 회귀 테스트

[중요: 필수 절차]
1. 작업 직전 git status 및 git log -1로 로컬 현재 상태 확인. 본 문서의 SHA는 작성 당시 스냅샷이다.
2. 현재 저장소의 실제 파일/CI/Console 존재 여부를 검토하고 변경 계획 제시 후 구현. 변경된 코드가 있으면 그대로 유지.
3. 사용자가 요구한 '두 오픈소스 활용'을 명확히 구현. 단순 README 비교로 끝내지 말 것.
4. @gurumnyang/dcinside.js는 외부 의존성으로 포장하고 한 모듈에서만 import. 단, 실제 DCInside 자동 요청은 사전 서면 동의/허용 범위 확인까지 기본 비활성화.
5. dcinside-deep-search는 원본 코드를 무단 복사/재배포하지 않고 사용자 내보내기(CSV/JSON) 결과를 받아들이는 별도 importer로 연계. 비슷한 dedup/정렬 로직은 독자 작성.
6. 기존 dc_search_posts, dc_parse_post_url, dc_import_post, dc_get_post, dc_get_comments의 이름 및 기본 인자/출력 유지.
7. API Key/쿠키/로그인 기능을 확장하거나 저장하지 않음. 로그인/글쓰기/삭제/추천 API는 범위 밖.
8. real endpoint 테스트는 기본 CI에서 호출하지 않음. 허용 증빙이 없는 경우 사용자가 제공한 fixture/mock으로 전체 기능 테스트.
9. 한 단계 완료할 때마다 해당 단계의 테스트 실행. 마지막에 통합 검증, 남은 제한사항, 로컬 실행 명령 기록.

[성공 판정]
- Brave 기반 갤러리 검색은 실행 가능하고 갤러리 ID 결과만 보여줌.
- 사용자 제공 deep-search CSV, JSON, HTML에서 게시글/댓글과 목록을 import하고 MCP에서 검색/조회 가능.
- 허가된 직접 조회 mode의 adapter는 별도 mock test로 실제 외부 호출 없이 통과하며, 허가 전에는 원격 요청 0회.
- Tool 계약/에러/출처가 UI/JSON 응답에 명확히 드러남.
- pnpm lint/typecheck/test/build 통과, 테스트 결과를 보고함.

[기타]
- 코드 주석, README는 간결하게. 사용자 보이는 UI는 한국어 중심, 기술 API 스키마는 영어.
- 명세 파일이 작업 결과 자체는 아니다. 저장소 실제 반영, 커밋/푸시는 사용자 명시적 지시에 따르되, 별도 승인 없이 원격 main 덮어쓰기/force push 금지.
