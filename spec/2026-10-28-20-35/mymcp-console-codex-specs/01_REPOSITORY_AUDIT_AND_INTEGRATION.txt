[3] 통합 원칙
- 기존 `apps/example/`, `mcps/dcinside/`의 public tool schema, transport, 저장 포맷을 무단 수정하지 않음.
- 기존 `mcps/google-routes/`, `mcps/japanese-vocab/`는 코드 존재와 실행 검증을 구분.
- 두 레거시 서버는 `planned` 혹은 `unverified`로 레지스트리에 나타내되, 기본 자동 실행 금지.
- 나중에 개별 package가 build + handshake + tool call 검증을 통과하면 supported로 전환.
- pnpm workspace에 이미 `mcps/*`가 포함되어 있으므로 중복 package discovery를 추가하지 않음.
- root scripts가 레거시 때문에 실패한다면 원인과 영향을 분석하여 최소 수정. 다른 패키지 테스트를 단순 삭제하거나 전부 제외하지 말 것.
- 콘솔과 MCP 서버는 독립 배포/실행 가능해야 하며, 콘솔만 빌드해도 모든 기존 MCP가 의도치 않게 변경되지 않도록 스크립트 필터 구성.

[4] 새 패키지와 네이밍
- `apps/console-server` => `@mymcp/console-server` (private, ESM)
- `apps/console-web` => `@mymcp/console-web` (private, Vite SPA)
- `packages/mcp-client` => `@mymcp/mcp-client` (Node-only)
- `packages/console-contracts` => `@mymcp/console-contracts` (browser-safe DTOs/Zod)
- Backend는 `packages/config/tsconfig.base.json` 기반 NodeNext, 상대 import .js.
- Frontend는 Vite에 맞는 tsconfig (bundler JSX) 사용. Node-only 패키지를 브라우저 번들로 가져오지 말 것.
- Frontend/App은 기존 ESLint 설정에 TSX, DOM global, React Hooks 규칙이 제대로 잡히도록 별도 override.
- pnpm lock 갱신은 패키지 변경과 동기화. `frozen-lockfile` CI 통과.
